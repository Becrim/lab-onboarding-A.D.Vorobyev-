## Назначение проекта

Проект реализует интерактивную систему из трёх модулей для анализа и выбора облачной платформы. Исходное задание использует файлы `.bat`; для запуска на macOS они заменены на shell-скрипты `.sh` с интерпретатором Bash.

Все скрипты рассчитаны на Bash 3.2 и не используют Bash 4+ функции, поэтому подходят для стандартного Bash в macOS.

## Структура проекта

- `chapter1.sh` — опрос о параметрах проекта и формирование рекомендации по платформе.
- `chapter2.sh` — учебное ревью пяти фрагментов кода, связанных с облачной инфраструктурой.
- `chapter3.sh` — сравнение Yandex Cloud, Selectel и Timeweb Cloud методом взвешенной суммы (WSM).
- `lab_system.sh` — главное меню, последовательный запуск модулей и формирование итогового отчёта.
- `common.sh` — общие функции проверки пользовательского ввода.
- `screenshots/` — каталог для снимков экрана работы модулей.
- `report.txt` — итоговый отчёт, создаваемый после запуска всех модулей или выбора пункта 5 главного меню.

## Запуск на macOS через Terminal

Перейдите в каталог репозитория:

```bash
cd ~/Projects/lab-onboarding-A.D.Vorobyev-
```

Сделайте скрипты исполняемыми:

```bash
chmod +x common.sh chapter1.sh chapter2.sh chapter3.sh lab_system.sh
```

Проверьте синтаксис всех скриптов:

```bash
for file in *.sh; do bash -n "$file" || exit 1; done
```

Запустите главное меню:

```bash
./lab_system.sh
```

Отдельный модуль можно запустить напрямую, например:

```bash
./chapter1.sh
```

Для формирования полного `report.txt` выберите в главном меню пункт **4** — все три модуля запустятся последовательно. Пункт **5** создаёт отчёт из результатов модулей, которые уже запускались.

## Описание модулей

### Часть 1. Моделирование процесса выбора технологий — `chapter1.sh`

Пользователю предстоит ответить на вопросы о приоритетах запуска MVP, ожидаемой нагрузке, опыте команды и подходе к бюджету. На основании ответов начисляются баллы трём кандидатам. Платформа с наибольшим результатом становится рекомендацией. При равенстве баллов пользователь выбирает одного из лидеров.

Оценочная модель является учебной эвристикой. Она не подменяет проверку актуальных тарифов, SLA, регионов доступности и конкретных облачных сервисов.

### Часть 2. Формализация процесса ревьюирования — `chapter2.sh`

Нужно определить тип дефекта в пяти фрагментах кода, имитирующих работу с облачной инфраструктурой:

1. Неинициализированная переменная при получении состояния виртуальной машины.
2. Мёртвое присваивание при выборе региона.
3. Утечка ресурса при чтении потока резервной копии.
4. Магическое число в пороге масштабирования.
5. Отсутствие обработки ошибок при создании облачного сервера.

За правильный ответ начисляется 2 балла, за ошибочный снимается 1 балл. Итоговый отчёт показывает количество правильных ответов, точность и уровень ревьюера.

### Часть 3. Сравнительный анализ альтернатив — `chapter3.sh`

Используется метод взвешенной суммы (WSM). Веса пяти критериев задаются пользователем; их сумма должна быть равна 100. Затем пользователь оценивает каждую платформу по шкале от 1 до 5.

Критерии:

- предсказуемость затрат;
- масштабируемость;
- наличие управляемых сервисов;
- контроль над инфраструктурой;
- простота запуска и администрирования.

Формула расчёта: `S = Σ(W × X)`, где `W` — вес критерия, `X` — оценка платформы. При сумме весов 100 результат приводится к шкале от 1 до 5. Победителем объявляется платформа с наибольшим итоговым баллом.

### Часть 4. Интеграция модулей — `lab_system.sh`

Главное меню позволяет запустить каждый модуль отдельно, выполнить все модули последовательно, сформировать отчёт или завершить работу. Результаты отдельных модулей сохраняются во внутреннем каталоге `.lab_state/`, а итоговый `report.txt` создаётся в корне проекта.
